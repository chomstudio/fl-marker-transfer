# パターンマーカー転送の実機検証

## 今回の変更

`Pattern Marker Transfer - Preflight Check.pyscript`を、コピー・直接編集・貼り付けを兼ねるテキスト欄1つの構成へ変更しました。置換チェックと専用の長文欄はありません。

起動時に現在の通常マーカーを暫定の1行JSONへ変換し、テキスト欄の初期値として渡します。内容を編集または別パターンのデータで上書きすると、デコードに成功した場合、通常マーカーだけを置換します。Accept／OKで確定、キャンセルで復元する構成です。ノート操作のAPIは使用しません。

旧版ではFL Studioが前回の入力を復元しました。今回は、入力欄の名前に起動ごとに変わる識別子を付け、名前に基づく復元の回避を試しました。パターンA・Bの切り替えで、それぞれの異なる情報が表示されたことを確認しています。FL Studio内部の復元方式そのものを特定した結果ではありません。ログの`入力欄名=`と`起動時データ=`でも比較できます。

## 準備

1. 更新した`.pyscript`で、FL Studioのユーザーデータフォルダ内の`Settings\Piano roll scripts`に配置した旧版を上書きします。
2. 必要ならスクリプト一覧を更新します。
3. 検証用に、通常マーカーの名前・位置が異なるパターンAとBを用意します。拍子・スケール変更マーカーとノートも残します。

スクリプト名は同じです。ダイアログには`マーカー情報 [xxxxxxxx]`というテキスト欄が1つだけ表示されます。末尾は起動ごとに変わります。

## 第1段階：起動時に現在の状態が表示されるか

まずこの段階だけを試してください。文字列の編集・貼り付けはまだ行いません。

1. パターンAでスクリプトを実行します。
2. テキスト欄の`name`と`time`が、パターンAの通常マーカーに対応しているか確認します。名前と位置は起動時の内容である必要があります。
3. キャンセルで閉じます。
4. パターンBへ切り替え、スクリプトを実行します。
5. 前回のAではなく、現在のBの内容が表示されるか確認します。
6. キャンセルで閉じます。閉じた後でDebugging logをコピーしてください。

報告するものは、AとBそれぞれで正しい現在値が表示されたかと、両起動の`[PMT Preflight]`ログです。ログは`入力欄名=`、`起動時データ=`、`文字列取得:`を含めてください。操作していないのに`起動時と一致=False`となる場合や、古い値・空欄が表示される場合は、そのまま確定せずキャンセルしてください。

ホストが起動時に`apply()`を呼ばない場合、文字列取得ログは出ない可能性があります。その場合も表示内容と起動時データを比較します。

## 第2段階：同じ欄を直接編集できるか

第1段階の結果を確認してから進めます。

1. 検証用パターンでスクリプトを実行します。
2. 同じ欄の通常マーカー1件について、`name`の文字列だけを書き換えます。最初は英数字など、JSONの引用符を壊さない内容にします。
3. 別の場所をクリックして入力を確定し、Previewを有効にしてマーカー名の変化を確認します。
4. キャンセルで閉じ、元の名前へ戻るか確認します。
5. もう一度同じ編集を行い、今度はAccept／OKで確定して閉じます。
6. 再実行せず、ピアノロールに変更が残るか確認します。

ログは閉じた後に確認します。文字列の編集がどの操作で反映されたかも記録してください。入力途中の不正JSONでは置換処理へ進みません。

## 第3段階：別パターンへコピーできるか

1. パターンAで実行し、テキスト欄をCtrl+A、Ctrl+Cでコピーしてキャンセルで閉じます。
2. パターンBで実行し、現在のBの内容が表示されたことを確認します。
3. 同じ欄をCtrl+A、Ctrl+VでAのデータへ置き換えます。
4. 通常マーカーがAの名前・位置に変わり、拍子・スケール変更マーカーとノートが保持されるか確認します。
5. まずキャンセルで復元を確認し、必要に応じて同じ操作を繰り返してAccept／OKでの確定も確認します。

ダイアログはモーダルです。開いたままログやエディターを操作する手順にはしません。

## データと判定の注意点

- 対象は旧版で確認した通常マーカーの種別です。新規`Marker()`の既定modeを使用し、確認済み環境では`0`でした。
- 転送形式は従来と同じ`PMT-preflight-1`の暫定JSONです。旧版のデータも使用できます。
- 起動時と同じマーカー内容なら削除・再追加を省略します。プレビュー中に元の文字列へ戻した際の復元は、FL Studio側のプレビュー処理も含めて確認対象です。
- 空欄や空白だけ、不正なJSON、異なるPPQやmodeのデータでは、その入力による置換を行いません。プレビュー済みの変更が取り消されることまで保証するものではないため、確定前に目視確認してください。
- `"markers":[]`は通常マーカーをすべて削除する有効なデータです。空欄とは区別します。
- 通常マーカーの変更はチェックなしで適用されます。起動時に古い内容が復元された場合も適用される可能性があるため、検証用パターンで試してください。
- 置換中に例外や`[FAIL]`が出た場合は、確定せずキャンセルして復元を確認します。
- 専用の4096文字テスト欄は削除しました。旧版で確認したのは初期値4096文字の取得・一致であり、入力欄の上限や外部コピーの完全性を確定したものではありません。

## ローカル検証と次の判断

代替APIで、入力検査、1欄の構築と初期値、再起動ごとの入力名、通常マーカーだけの置換、繰り返し置換、0件データ、起動時と同じ内容では置換しないことを検査します。実機の入力復元・プレビュー・キャンセル動作は再現していません。

```powershell
python codexdocs/test_pattern_marker_transfer_preflight.py
```

現行版の基本操作はユーザーによる実機確認を完了しました。次は別プロジェクト向けの本体仕様を検討できる段階です。すべての変更ファイルはGit除外対象の`codexdocs/`内にあります。

## 1欄構成の実機確認結果（2026-10-17）

ユーザーが共有したA・Bの表示文字列と操作結果に基づきます。両パターンのPPQは96、FL Studioのバージョン／buildは未取得です。

| 項目 | 結果 |
| --- | --- |
| 起動時の表示 | A・Bの各パターンで、それぞれ異なる通常マーカー5件の情報を表示。 |
| 直接編集 | 同じ欄のマーカー名を編集すると、実際のマーカー名に反映。 |
| キャンセル | 直接編集後にキャンセルすると元の名前へ復元。 |
| 別パターンへの転送 | Aでコピーした文字列をBの同じ欄へ貼り付け、通常マーカーをAの内容に置換。 |
| 対象外の保持 | 転送時に拍子・スケール変更マーカーへの影響なし。 |
| 確定 | Accept／OKで閉じた後も転送結果を保持。 |

基本のUIは「1欄に現在値を表示し、その欄でコピー・直接編集・貼り付けを行う」方式で実現可能と判断します。入力名を起動ごとに変える現行方式を含む結果であり、固定名の1欄でも同様に動くとまでは確認していません。

不正入力、0件データ、同時刻マーカー、長文の外部コピー・貼り戻しなどは、現行版での追加実機確認は行っていません。直接編集だけをAcceptで確定するケースと、貼り付け後にキャンセルするケースも、現行版では個別確認していません。これらは基本機能の実現可能性と分けて、本体の検証項目に引き継ぎます。

## 旧版の実機確認結果（2026-10-17）

ユーザー提供のログと目視結果に基づきます。PPQは96、今回の実機確認に使用したFL Studioのバージョン／buildは未取得です。

| 項目 | 結果 |
| --- | --- |
| 通常マーカーの識別 | `mode=0`。新規`Marker()`の既定値も`0`。 |
| 対象外マーカーの識別 | 拍子変更は`mode=8`、キー／スケール変更は`mode=12`。 |
| 通常マーカーだけの抽出 | 通常3件を抽出し、拍子・スケール変更は転送データから除外。 |
| 文字列の入出力 | コピー用欄156文字が起動時と一致。貼り付け156文字から3件をデコード。 |
| 日本語・記号・絵文字 | ラベルの転送・置換と、読み戻し結果の一致を確認。 |
| 長文欄の初期値 | 4096文字を取得し、完全一致。長文の外部コピー・貼り戻しは未確認。 |
| 別パターンへの置換 | 通常3件の名前・位置・件数が一致。 |
| 対象外の保持 | ログとユーザー確認により拍子・スケール変更を保持。ノートも変更なしとの報告。 |
| キャンセル | ユーザー目視で元のマーカーへ復元。キャンセル操作の種類別確認は未実施。 |
| 確定 | 確定後の目視で通常マーカーがコピー元と一致し、対象外マーカーへの影響なし。 |
| モーダル動作 | ダイアログを閉じるまでログのコピーなど、ほかの操作は不可。 |
| 前回入力の復元 | 再実行時に前回の入力内容が復元される。起動時の自動プレビューを考慮する必要あり。 |

旧版の時点では、前回入力の復元による意図しない再適用と、コピー用欄へ古い情報が表示される可能性が課題でした。その後の1欄構成と入力名変更による検証結果は、前節に記録しています。

不正入力、0件データ、同時刻マーカー、PPQが異なる場合の扱い、長文の外部コピー・貼り戻し、別チャンネルからの参照は、このスクリプトの実機結果としては未確認です。入力検査や0件データの置換などの一部は代替APIでのみ確認済みです。
