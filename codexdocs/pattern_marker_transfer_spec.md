## 1. 位置づけ

Pattern Marker Transferは、FL Studioの通常のパターンマーカーを文字列としてコピー・編集・貼り付けするピアノロールスクリプトである。名称は仮称とする。

Marker Scale Guardとは別の単体プロジェクトとして実装する。コード名・キー名・スケール情報の解析は行わず、ラベルをそのまま扱う。本仕様書は新規プロジェクトへ移して単独で使用できるものとする。

本仕様は検証済みの1欄構成を採用する。正式な転送形式と入力エラー時の動作は、本体向けに本書で定義したものであり、すべてが検証用スクリプトへ実装済みという意味ではない。

## 2. 実現すること

- 起動時に、現在のパターン内の通常マーカーの件数・位置・ラベルを取得する。
- マーカー情報を1つのテキスト欄へ表示し、ユーザーがコピーできるようにする。
- 同じ欄を直接編集、または別パターンからコピーした情報で上書きし、現在の通常マーカー全体を置き換える。
- プレビューで結果を確認し、FL Studio標準のAccept／OKで確定、キャンセルで起動時の状態へ戻す。
- 拍子変更・キー／スケール変更マーカー、およびノートは変更しない。

## 3. 動作環境・実装方式

- ピアノロールスクリプトAPIを利用できるFL Studioを対象とする。
- Pythonの`.pyscript`として実装し、`flpianoroll`とPython標準ライブラリだけを使用する。
- 外部Pythonのインストール、外部パッケージ、設定ファイル、常駐プロセスは利用に必要としない。
- ユーザーデータフォルダの`Settings\Piano roll scripts`以下へ配置する。
- 現在開いているピアノロールの`score`を通して、現在のパターンに属するマーカーを扱う。
- 別パターンを直接指定して読み書きする機能は設けない。パターンの切り替えはダイアログを閉じてからユーザーが行う。
- クリップボードへの読み書きはテキスト欄の標準操作を使う。専用のコピー・貼り付けボタンやOS固有のクリップボード処理は不要とする。

## 4. 対象データ

### 4.1 マーカーの種類

通常の名前付きパターンマーカーを対象とし、`Marker.mode == 0`で判別する。ラベルの内容から種別を推測しない。

実機検証では通常が`0`、拍子変更が`8`、キー／スケール変更が`12`であった。対象外は`8`と`12`だけに限定せず、`mode != 0`のすべてとする。

新規`Marker()`の既定modeも`0`であることを確認済みだが、本体では対象のmodeを明示する。既定値が違うという理由で対象種別を自動的に変更しない。

### 4.2 転送する情報

- 各マーカーの位置：パターン先頭を`0`とする絶対tick値。
- 各マーカーのラベル：取得した文字列全体。
- コピー元のPPQ：tickの解釈が一致するかを検査するための情報。
- 転送形式の識別子と対象mode。

選択状態やピアノロールの時間範囲選択にかかわらず、通常マーカー全件を対象とする。最初のマーカーの位置を自動的に`0`へ移動する処理は行わない。貼り付け位置は4.4節の小節単位オフセットで指定する。

転送データの解析、配置位置の計算、ホストへの置換を分離する。配置計算は元データを変更せず、変換後の全位置を削除前に検査する。復元時は配置計算を通さず起動時の位置を使用する。

### 4.3 保持する情報

- 対象外マーカーの位置、名前、mode、拍子やスケールなどの付加情報。
- 全ノートの位置・音程・長さ・選択状態など。
- プロジェクトのPPQ、テンポ、拍子、その他の設定。

対象外マーカーを一旦削除して作り直す方法は使わない。`clear()`や`clearMarkers()`による一括消去も使用しない。

### 4.4 貼り付けオフセット

- 整数の小節数を指定する。初期値は`0`。
- 「1小節」は起動時に取得した貼り付け先の基本拍子（`score.tsnum`、`score.tsden`）とPPQで固定し、パターン内の拍子変更マーカーには追従しない。コピー元の拍子は転送しない。
- 1小節のtick数は`PPQ × 4 × 拍子の分子 ÷ 拍子の分母`。整数tickで表現できない場合や基本拍子を取得できない場合は、丸めず編集の開始を中止する。
- `0`は元の絶対tick位置へ貼り付ける。正の値は指定小節分だけ後ろへ移動する。`1`なら元の位置に1小節分を加える。
- 負の値は先頭から指定小節分を切り落として、残ったマーカーをその分だけ前へ詰める。`-2`なら元の位置から2小節分を引き、結果が負になるマーカーを除外する。結果がちょうど`0`なら保持する。除外したラベルを先頭へ補完する処理は行わない。
- 元の配列が1件以上で、切り落としによって0件になった場合は正常な「変更なし」とする。コピー先の通常マーカーを全削除しない。途中で別の結果をプレビューしていた場合は起動時の状態へ戻す。
- 元から`markers:[]`である有効なデータは、オフセットにかかわらず通常マーカー全件の削除を意味する。切り落としによる0件と区別する。
- 正方向へ移動した結果が`2147483647`を超える場合は全件拒否し、起動時の状態へ戻す。
- オフセットの指定範囲はノブ・付属の数値欄ともに`-16`〜`+16`小節とする。ホイール1刻みで1小節ずつ調整する。スクリプト側でもこの整数範囲を検査し、範囲外や型違いの値は拒否して起動時の状態へ戻す。
- ノブとは別の直接指定欄や、±16を超える値の指定機能は設けない。配置後のtick位置の上限は別途検査する。
- オフセットは今回の貼り付け操作に対する設定とし、JSONの形式・内容には含めない。コピー欄の出力は起動時の絶対位置のままとする。直接編集にも同じオフセットを適用する。

PPQ=96・基本拍子4/4なら1小節は384tick。`-2`では768tick未満を除外し、768tickのマーカーは0tickへ、800tickのマーカーは32tickへ配置する。

## 5. ダイアログ

### 5.1 構成

- タイトル：`Pattern Marker Transfer`。
- 説明文：現在の通常マーカー件数と、コピー・直接編集・貼り付けの操作を簡潔に表示する。
- マーカー情報のテキスト入力欄：1つ。表示名の基本部分を`マーカー情報`とする。
- 整数ノブ：1つ。表示名の基本部分を`貼り付けオフセット（小節）`とし、操作範囲は`-16`〜`+16`、初期値は`0`とする。説明文に基準の拍子と1小節のtick数、正負の意味、全件除外時は変更なしになることを表示する。
- 確定・キャンセル・Preview：FL Studioが用意する標準UIを使用する。

入出力欄の分離、置換を有効にするチェックボックス、長文テスト専用欄は設けない。

### 5.2 起動時の現在値

起動のたびに現在のマーカーを読み取り、その内容をテキスト欄へ表示する。直前のパターンで表示・編集した文字列を初期表示として復元してはならない。

FL Studioは前回の入力内容を復元する場合がある。検証済み方式として、`マーカー情報 [xxxxxxxx]`のように起動ごとに異なる識別子を入力欄名へ付ける方法を採用できる。同一の起動内では入力欄名を固定する。この識別子は転送データへ含めない。

固定の入力名へ変更する場合は、パターン切り替え後の現在値が必ず表示されることを別途実機で確認する。APIに存在が確認できていない入力値更新メソッドを前提にしない。

ノブの入力名にも同じ起動識別子を付け、再起動時は必ず`0`で初期表示する。前回のオフセットを意図せず再適用しない。

### 5.3 プレビューと終了

有効な内容を編集・貼り付けした場合は、標準のPreviewの状態に従って置換結果を反映する。キー入力の1文字ごとに必ず更新されるとは保証せず、入力確定やフォーカス移動など、ホストが`apply()`を呼ぶタイミングに従う。

確定後は最後の有効な入力による結果を保持する。ただし最終入力が空欄または不正である場合は、7節の方針を優先する。キャンセルまたは右上の閉じる操作では起動時の状態を保持する。

起動時と同じ内容をオフセット`0`で表示して閉じるだけなら、マーカーを実質的に変更しない。オフセットを繰り返し変更しても、毎回入力データから配置を計算し、直前のプレビューへ加算しない。

ダイアログはモーダルである。開いたままログのコピー、エディター操作、パターン切り替えを行う案内はしない。

## 6. 転送文字列

### 6.1 正式形式

標準ライブラリのJSONで読み書きできる、次の形式をバージョン1とする。

```json
{
  "format": "PMT-1",
  "ppq": 96,
  "mode": 0,
  "markers": [
    { "time": 0, "name": "イントロ" },
    { "time": 384, "name": "Aメロ" }
  ]
}
```

| キー      | 型・条件                      | 意味                               |
| --------- | ----------------------------- | ---------------------------------- |
| `format`  | 文字列`PMT-1`                 | 形式とバージョンの識別子。         |
| `ppq`     | 正の整数                      | コピー元の1拍あたりのtick数。      |
| `mode`    | 整数`0`                       | 通常マーカーのみを扱うことを示す。 |
| `markers` | 配列                          | 通常マーカー全件。0件は空配列。    |
| `time`    | `0`以上`2147483647`以下の整数 | マーカーの絶対tick位置。           |
| `name`    | 文字列                        | マーカーのラベル。                 |

`time`の上限は検証スクリプトと同じ入力検査上の制限であり、FL Studioの全バージョンで作成可能な最大位置を保証する値ではない。

### 6.2 出力規則

- 初期表示は改行のない1行とし、不要な空白を省く。
- 日本語・絵文字は可能な限りそのまま出力し、引用符・バックスラッシュ・制御文字はJSONの規則でエスケープする。
- ラベルの前後の空白、連続空白、文字の大文字小文字、Unicodeを勝手に正規化しない。
- マーカーは時刻の昇順とし、同時刻では取得時の順序を保持する。
- 同名・同時刻を理由とする重複排除はしない。

### 6.3 入力規則と互換性

- `PMT-1`に加え、今回の検証データの`PMT-preflight-1`も同じ構造として受け付ける。出力は常に`PMT-1`とする。
- 入力のJSONには空白や改行があってもよい。JSONのキー順序には依存しない。
- 必須キーの欠落、型の不一致、不明な形式、範囲外の時刻、NUL文字を含むラベルは不正とする。空のラベル文字列は許可する。
- 整数の位置へ真偽値や小数を受け付けない。
- 定義外のキーおよび同一オブジェクト内の重複キーは、不正として報告する。解釈の異なる情報を黙って捨てない。
- 入力の`ppq`と現在の`score.PPQ`が一致しなければ拒否する。バージョン1ではPPQ変換を行わない。
- すべての行を検査し、1件でも不正なら全件を適用しない。
- 同時刻マーカーも入力上は保持する。ホストが表現できない組み合わせを黙って統合・欠落させない。保持できない場合は適用を失敗として扱う。

## 7. 空欄・不正入力・エラー

### 7.1 空欄と0件データ

空欄または空白だけの入力は「変更なし」とする。通常マーカーをすべて削除する操作にはしない。

有効なJSONの`"markers":[]`は「通常マーカー全件を削除する」とする。対象外マーカーは保持する。起動時に通常マーカーが0件でも、空欄ではなくこの有効なJSONを表示する。

負のオフセットによる切り落としで0件になった場合は、4.4節のとおり正常な「変更なし」とする。起動時の状態を採用し、通常マーカー全件の削除へは進まない。

### 7.2 編集途中の不正入力

JSONを直接編集するため、途中で不正になることは通常の操作として扱う。その入力による置換は行わず、原因をDebugging logへ記録する。`apply()`内でモーダル警告を繰り返し表示しない。

最終入力が空欄または不正である場合は、途中でプレビューした変更を残さず、起動時の状態を採用して終了する方針とする。この動作は検証用スクリプトでは実機確認していないため、本体で実装・実機検証する。

ホストのプレビュー復元機構を利用してもよいが、単に`apply()`を早期終了すれば必ず元に戻ると仮定しない。正しい入力から不正入力・空欄・起動時の文字列へ戻す遷移を検査する。必要なら通常マーカーの起動時スナップショットを明示的に復元する。

標準APIの制約によりエラー時の確定防止や状態表示が難しい場合も、起動時の状態を守る方針を優先する。実現できない点が判明した場合は仕様上の課題として報告し、直前のプレビューを黙って確定する動作へ変更しない。

### 7.3 API操作の失敗

起動時の読み取りに失敗した場合は編集を開始せず、理由を表示またはログへ記録する。

置換中の追加・削除・読み戻しに失敗した場合は、起動時の通常マーカーへ復元を試み、失敗を記録する。復元にも失敗した場合は、復元できたとは報告せず、キャンセルによる確認が必要であることを記録する。対象外マーカーを復旧目的で削除しない。

## 8. 実装上の要件

1. ダイアログ生成前に、現在のPPQ、基本拍子とマーカー情報を通常のPythonデータへ退避する。マーカー件数は走査前に一度取得して固定する。
2. テキスト入力を全件デコード・検査し、追加用マーカーオブジェクトを準備してから削除へ進む。
3. 現在の通常マーカーだけをインデックス降順で削除する。
4. デコードした通常マーカーを追加する。繰り返しの`apply()`で追加件数が累積しないよう、毎回同じ最終状態を作る。
5. 配置計算後の内容が現在の通常マーカーと同じなら削除・再追加を省略できる。ただしプレビュー編集後に元の文字列とオフセット0へ戻した場合の復元を省略しない。
6. 置換後は名前・位置・件数を読み戻して照合する。対象外マーカーも付加情報を含めて保持を検査する。列挙順が変わるだけのケースと実データの変更を区別する。
7. ホストが同時刻の対象外マーカーを上書きするなどの制約があれば、事前に判定できる条件は削除前に拒否する。未検証の組み合わせを正常動作として報告しない。

初回版では通常マーカーを対象外マーカーと同じ位置へ新規追加する置換を拒否する。また、起動時から通常・対象外マーカーが同じ位置で共存するパターンでは、復元時の再追加も安全性を確認できていないため、内容が変わる置換を削除前に拒否する。現在値の表示・コピーと、同じ内容の適用は可能とする。この制限の緩和には実機確認が必要である。

## 9. 今回の範囲外

- 拍子変更・キー／スケール変更マーカー自体の転送。
- コピー先への追記、選択範囲だけの転送、PPQ変換、拍子変更に追従するオフセット計算。
- ファイルへの保存・読み込み、クリップボードの自動取得。
- Marker Scale Guard固有のラベル文法の検査。
- 複数パターンの一括操作、Playlistのマーカー操作。

## 10. 実機検証の結果と限界

2026-10-17にユーザー提供のログと操作報告で、次を確認した。PPQは96。今回使用したFL Studioのバージョン／buildは未取得であり、既存の別スクリプトの動作環境から推測して記載しない。

| 項目                 | 結果                                                                                          |
| -------------------- | --------------------------------------------------------------------------------------------- |
| 種別識別             | 通常0・拍子8・スケール12。                                                                    |
| 起動時の1欄表示      | パターンA・Bで、それぞれ異なる通常マーカー5件の情報を表示。入力名には起動ごとの識別子を使用。 |
| 直接編集             | ラベルの変更がマーカーへ反映され、キャンセルで復元。                                          |
| 別パターンへ貼り付け | 同じ欄へ上書きし、コピー元の通常マーカーへ置換。                                              |
| 対象外の保持         | 拍子・スケール変更マーカーに影響なし。旧版ではノートの保持も確認。                            |
| 確定                 | 貼り付け後のAccept／OKで置換結果を保持。                                                      |
| Unicode              | 日本語・記号・絵文字のラベルを取得・転送。                                                    |
| 長文                 | 旧版の専用欄で4096文字の初期値を完全一致で取得。入力上限や外部コピーの完全性の確認ではない。  |

検証済みなのは暫定JSONと基本の正常操作である。正式形式の厳密な入力検査、不正入力後の復元、同時刻マーカー、0件データ、PPQ不一致、長文、ホストAPI例外の処理は、本体で検証する必要がある。

## 11. 本体の受け入れ条件

- パターンを切り替えた後も、前回値ではなく現在の通常マーカー情報を1欄へ表示する。
- 編集なしで確定・キャンセルした場合、マーカーやノートを実質的に変更しない。
- コピー、直接編集、別パターンへの貼り付けを同じ欄で行える。
- 直接編集・貼り付けのそれぞれで、プレビュー・確定・キャンセルが期待どおり動く。
- 対象外マーカーの付加情報と全ノートの状態を保持する。
- 日本語・記号・絵文字・引用符・バックスラッシュ・ラベルの空白を保持する。
- 正式形式と検証用形式を読み込み、正式形式で出力する。
- 不正データ、型違い、PPQ不一致は削除前に全件拒否する。
- 正常なプレビューから不正入力・空欄・起動時の文字列へ戻して確定しても、起動時の状態を保持する。
- 0件のパターンで起動でき、有効な空配列による削除は通常マーカーだけに限定する。
- Previewや入力を繰り返し変更してもマーカーが累積・欠落しない。
- 基本拍子から小節単位のオフセットを計算でき、正方向の移動、負方向の切り落とし、境界ちょうどの保持が正しい。
- 切り落としで全件除外された場合は正常な変更なしとし、コピー先を全削除しない。先行プレビューがあれば起動時へ戻す。元から空配列の場合は従来どおり全削除する。
- オフセットの変更を繰り返しても累積せず、再起動時は0になる。範囲外の移動先は削除前に拒否する。
- オフセットのホイール1刻みが1小節の増減になること。専用の直接指定欄は表示せず、ノブと付属の数値欄の範囲を-16〜+16に限定すること。
- 同時刻の通常マーカーや対象外マーカーとの共存は、保持できるかを実機確認し、失敗時は成功扱いしない。
- 長文は実機で表示・選択・コピー・貼り付けを往復検査する。未確認の文字数上限を保証しない。

ローカルの代替APIテストとFL Studio実機検証を区別し、結果を開発状況書に記録する。
